## Assumptions

Decided on the builder's behalf (change any that are wrong):

- The earlier toggle-mode decisions are already built and merged; this request does not change them.
- The 28 new names are my choice from the builder's examples plus common everyday actions: search, filter, sort, copy, paste, back, next, home, menu, more, settings, help, info, warning, send, login, logout, undo, redo, approve, reject, favorite, attach, lock, unlock, archive, export, import.
- The library today has 19 built-in names (the request says 17 types because some are aliases); after this change it has 47.
- Defaults for the new types follow R2; only the async actions get a 500 ms minimum busy time and none ask for confirmation.
- The standardized icons are also exported as a ZestIcon component so developers can reuse them; this is additive.
- The change is released as a minor version (1.6.1 to 1.7.0) with a note in breaking-changes about the new icon art, since no prop or export is removed.
- react-icons stays a peer dependency because the spinner and dropdown arrow still use it.

## Out of scope

- A separate switch control with a sliding track and knob
- Changing the busy spinner or the dropdown arrow icons (they keep using react-icons)
- Animating the type icons
- Custom per-app icon packs or an icon picker
- Colour-filled or multi-colour icons
- Translating button labels: the label always comes from the developer's children
- Removing react-icons from the peer dependencies
- More than the 28 new types chosen by the builder

## Role documentation

### Analyst: requirements

ZestButton gets a much wider set of built-in semantic types (about 28 new ones on top of the 19 names it has today, covering navigation, search and filter, clipboard, account, status and approval actions) and every built-in type, old and new, shows an icon drawn by the library itself as inline SVG in one consistent style (same grid, line weight, rounded ends, uses the button's text colour). This replaces the Font Awesome icons the built-in types use today. Developers who install the library get a ready icon and sensible default look for common actions by writing only zest={{ semanticType: 'search' }}; their end users see matching, crisp icons in light, dark and system themes. Existing props, types and unknown-type behaviour do not change.

### Architect: design

Additive icon layer on the existing semantic-type system, with no new framework, dependency or build-output change. A new internal module, UI/zestIcons.tsx, owns the 47 built-in names' path data and a module-level map of React SVG elements that are created once at import (aliases deliberately share one element). A new public component, UI/ZestIcon.tsx, looks a name up in O(1), renders the shared element unchanged, hides it from screen readers (aria-hidden + focusable=false) and returns null for unknown names; an optional size and className are applied by a thin wrapper so the shared SVG element is never cloned or rebuilt. UI/semanticTypeButtonConfigDefaults.tsx drops every react-icons/fa import and uses those shared elements as iconLeft (or iconRight for view, details and next) for the existing entries, keeping their order and every option they have today; confirm gains the standard check icon because R3 requires an icon on every built-in type. The same file appends exactly the 28 new entries with the R2 defaults: standard solid variant and iconLeft for search, filter, sort, copy, paste, home, menu, more, settings, help, info, favorite, attach, lock, unlock, undo, redo; back uses iconLeft, next iconRight; approve is success, reject and warning are danger; send, login, logout, export, import, approve, reject and archive get only busyOptions.minBusyDurationMs = 500 (no successOptions, no confirmOptions). UI/ZestButton.tsx only widens the SemanticType union from 19 to 47 names. UI/index.ts adds the ZestIcon, ZestIconProps and ZestIconSize exports. Existing CSS Modules, the styles.icon slot, currentColor theming and the existing useZestConfig precedence/deep-merge are reused; one .zestIcon rule is added for size in em (font sizes are already rem based). No change to useZestConfig, react-icons (FaSpinner and the dropdown chevron stay), rollup, peer or runtime dependencies, or the dist layout. Public surface: added ZestIcon/ZestIconProps/ZestIconSize; extended SemanticType; no existing export, prop or type removed or renamed. Release: package.json and package-lock.json go to 1.7.0 and documentation/breaking-changes.md gets a 1.7.0 entry for the new icon art. Scale/cost: the number of built-in types is fixed at 47, lookup is a single object property read, the 47 SVG elements and their path strings are allocated once at module load (a few KB), and per button, per render the work is constant; 100x more buttons only adds the unavoidable DOM nodes, with no loops over the type list, no caches that grow, no timers, listeners, network or storage.
