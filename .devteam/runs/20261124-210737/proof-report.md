## Role documentation

### Analyst: requirements

This is revision 1 of 3 of a larger feature (R1 to R5). ZestButton gains two opt-in options on its existing `zest` configuration object. `focusSheen` (default off) plays the split button's diagonal light streak across the whole button when the button receives keyboard focus, and `sheenTrigger` (a changing string or number) lets the host play the same streak from code, with or without focus. The effect is decorative: clipped to the button, shown on every button style and theme, one sweep per focus arrival or per trigger change, and switched off under prefers-reduced-motion. It exists so keyboard users can spot which button has focus on screens full of controls.

### Architect: design

Revision 1 of 3: adds only the opt-in focus streak; the programmatic trigger belongs to a later revision and is not built here. One optional field joins the already-exported custom-props object, so useZestConfig's existing provider -> semantic -> local deep merge carries it through: no new export, no barrel change, no context, no dependency, and a button that omits the field renders and behaves exactly as today. The effect is pure CSS, with no React state, listeners or timers. A regular button gets a modifier class and a pseudo-element streak clipped by the button's existing position:relative, overflow:hidden and 8px radius. A split button gets the same modifier class on the existing split wrapper, which gains position:relative plus the existing force-light/force-dark theme class and small style/variant marker classes; the band is clipped by the overlay's own border-radius rather than by wrapper overflow, deliberately, so neither segment's outer focus ring is cut (R5). The overlay is driven by :has(:focus-visible) on the wrapper, so keyboard focus on either segment plays one whole-control sweep and a mouse click plays none; the wrapper's opted-in class also switches off the chevron's mount streak through a descendant rule, with no change to ZestDropdownMenu. The band is a diagonal ~45-degree gradient that travels top-right to bottom-left in ~0.6s, one sweep, ending transparent. Colour is derived from currentColor for the regular button (white on solid matches the existing chevron look; the accent colour on outline/text/dashed stays visible per style, variant and forced theme) and from a dedicated custom property chosen by style+variant+theme markers for the split overlay. Reduced motion disables both. Cost: when off there is no extra DOM and no CSS match, so behaviour and resource use are unchanged; when on the work is one pseudo-element layered paint animation, with no layout shift and no network, storage or startup cost. No dependency or build-output change (the project has no .size-limit.json; the stylesheet grows by a few hundred bytes).
