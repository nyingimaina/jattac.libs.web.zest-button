## Role documentation

### Analyst: requirements

This is revision 3 of 3 of a larger feature (R10 to R13). ZestButton gains two opt-in options on its existing `zest` configuration object. `focusSheen` (default off) plays the split button's diagonal light streak across the whole button when the button receives keyboard focus, and `sheenTrigger` (a changing string or number) lets the host play the same streak from code, with or without focus. The effect is decorative: clipped to the button, shown on every button style and theme, one sweep per focus arrival or per trigger change, and switched off under prefers-reduced-motion. It exists so keyboard users can spot which button has focus on screens full of controls.

### Architect: design

Revision 3 is the hardening and release pass for the focus streak already built in revisions 1 and 2; it adds no component logic, no style rule, no export and no dependency. The existing implementation already satisfies the behavioural core of R10 and R13: every streak layer is a pseudo-element with pointer-events:none, an absolute inset:0 box that cannot shift layout, no ARIA/DOM/focusable node and no tabindex on the split wrapper; the focus ring remains the only real focus signal; the sweep is a one-shot CSS animation (1 iteration, fill both, ending at opacity 0) plus the existing useSheenTrigger state helper, which uses no timer, interval, requestAnimationFrame, listener, observer or retained subscription, and package dependencies are unchanged. This revision therefore turns those guarantees into a durable contract: new R10 decoration tests (click-through, identical accessible tree, hidden layer, no layout shift), new R13 scale tests (100 opted-in buttons with zero scheduled timers, no document listeners or observers attributable to the streak, animation bounded to one pass, dependencies unchanged), extra R12 characterization cases alongside the existing baseline for the split wrapper, chevron mount streak and focus ring, and a new R12 release-surface guard. R11 is completed by adding the one missing consumer document, an additive 'no breaking changes' note for version 1.9.0 in documentation/breaking-changes.md while keeping its previous/next links; README, API, features, examples, configuration and the focus-streak guide already document both options and are verified rather than rewritten.
