## Implementation deviations from the BRS's Technical Design (discovered during implementation, not guessed)

1. **The JSX-runtime inlining was the real React 19 blocker, not the peer range.** The BRS originally scoped only a peer-range change plus verification; while investigating the user's "support vite" addendum, `dist/index.esm.js` was found to contain `reactJsxRuntime_production_min`, `Symbol.for('react.element')`, and a `ReactCurrentOwner` read. The BRS was updated to make externalizing the JSX runtime an explicit acceptance criterion (AC 5) and the fix a first-class deliverable. The peer-range change alone would have advertised support that did not work.
2. **The `.d.ts` bundle `external` array was also updated** to list the JSX-runtime subpaths, for consistency with the JS bundle. Not strictly required (the declarations reference the `React` namespace, not the JSX runtime), but keeps the two arrays aligned and the `buildExternalization` guard honest.
3. **Vite verification used a scratch harness, not a repo dependency.** A throwaway project under the OS temp dir installed Vite 5 + React 19 and consumed the `npm pack`ed tarball. This exercises the real published surface (`files`, `exports`) without adding Vite to this repo's devDependencies (which the BRS keeps out of scope).

## Notes

- The `version` field is intentionally **not** bumped (this repo bumps versions in separate `feat: bumped version to X` release commits). A **major** bump is required before this peer-floor change reaches consumers, and is documented in `documentation/breaking-changes.md` as "Version 2.0.0 (unreleased)".
- React 19 verification is point-in-time (the repo has no CI). The two guard tests protect the declaration and the externalization permanently; re-running the React 19 install remains a manual step until CI is added.
- React 16.8/17 consumers now get an unmet-peer warning; this is intentional and documented.
